Module-by-Module Technical Breakdownmain.py (Orchestration & Entry Point):Initializes simulation parameters (time limits, resource constraints, thresholds).Triggers the main asynchronous event loop.Calls the reporting module to compile and save the visual output.simulator.py (Event Loop & Timeline Controller):Manages temporal ticks and asynchronous task scheduling using Python's asyncio.Coordinates real-time synchronization between incoming workloads and available server nodes.autoscaler.py (Decision Engine):Houses the greedy threshold policy algorithms.Continuously monitors aggregated CPU load across active nodes.Evaluates scale-out triggers (>75% load) and scale-in triggers (<30% load).compute_resource.py (Virtual Node Lifecycle):Simulates individual server nodes (CPU capacity, active processing state, provisioning delay).Manages state transitions: Initializing $\rightarrow$ Active $\rightarrow$ Overloaded $\rightarrow$ Terminated.workload.py (Traffic Generator):Generates dynamic, multi-phase request streams simulating real-world traffic patterns (e.g., morning spikes, steady-state, sudden bursts, evening lulls).2. Step-by-Step Simulation WorkflowPhase 1 — Initialization: The event loop spins up with a baseline number of active compute nodes and a predefined multi-step workload scenario.Phase 2 — Request Ingestion: The workload generator feeds concurrent user requests into the system timeline.Phase 3 — Load Evaluation: Active compute nodes process requests, and their individual/aggregate CPU utilization metrics are updated in real-time.Phase 4 — Threshold Interception:If aggregate CPU utilization exceeds 75%, the autoscaler immediately provisions a new virtual node.If aggregate CPU utilization drops below 30%, the autoscaler flags idle nodes for safe de-provisioning.Phase 5 — Telemetry & Analytics: Runtime states are logged to the console, and a final summary script renders the Matplotlib performance chart (autoscaler_report.png).3. Key Engineering HighlightsNon-Blocking Concurrency: Built using native asyncio to handle simultaneous request processing and node status updates without thread-locking overhead.Cost vs. Performance Optimization: Strips away the complexity of commercial cloud tools (like AWS Auto Scaling) while perfectly mirroring their underlying threshold logic for academic and simulation purposes.Automated Visual Verification: Eliminates manual log parsing by generating clear graphical timelines mapping resource count against CPU spikes.
